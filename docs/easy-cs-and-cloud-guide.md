## 1. 🍽️ 식당에 비유하는 웹 서비스의 기본 구조 (프론트엔드 vs 백엔드)

웹 서비스를 근사한 **레스토랑**에 비유하면 쉽게 이해할 수 있습니다!

```text
  [ 🧑 손님 (사용자) ]
          │ (메뉴판 보고 주문 / 클릭)
          ▼
  [ 🍷 홀 & 인테리어 (프론트엔드: React) ]
          │ (주문서 전달 / REST API)
          ▼
  [ 👨‍🍳 주방 & 요리사 (백엔드: FastAPI) ]
          │ (식자재 꺼내기)
          ▼
  [ 🧊 냉장고 & 창고 (데이터베이스: SQLite) ]
```

### 🍷 1) 프론트엔드 (Frontend - React) = "식당 홀 & 메뉴판"
- **역할**: 손님이 들어와서 앉는 예쁜 테이블, 메뉴판, 주문 버튼입니다.
- **예시**: 사용자가 브라우저에서 보는 화려한 화면, 버튼 클릭, 파일 업로드 창.
- **기술**: React 19, TypeScript, Nginx (홀을 청결하게 유지하는 관리자)

### 👨‍🍳 2) 백엔드 (Backend - FastAPI) = "주방 & 요리사"
- **역할**: 손님이 눈에 보이지 않는 주방 안쪽입니다. 손님의 주문(클릭)을 받아 음식을 조리(데이터 계산)하고 전달합니다.
- **예시**: 로그인 비밀번호 맞는지 확인하기, 파일에서 글자 뽑아내기, 강사 점수 계산하기.
- **기술**: Python, FastAPI, Uvicorn

### 🧊 3) 데이터베이스 (Database - SQLite) = "식자재 냉장고"
- **역할**: 강사들의 연락처, 이력, 과업지시서 데이터가 유통기한 없이 안전하게 보관되는 냉장고입니다.

## 2. 📦 '도커(Docker)'란? (모든 재료가 들어있는 밀키트)

옛날에는 내 컴퓨터에서 잘 되던 프로그램이 다른 컴퓨터나 구글 서버로 옮기면 "왜 안 되지?" 하고 고장 나는 일이 많았습니다. (파이썬 버전이 다르거나, 필요한 프로그램이 안 깔려있어서 발생)

### 🍱 도커(Docker)의 핵심 원리: "밀키트(Meal Kit)"
- 도커는 **소스코드 + 실행 프로그램 + 필요한 양념(라이브러리)**을 **하나의 상자(컨테이너)** 안에 몽땅 밀봉해 포장해 주는 기술입니다.
- 마치 밀키트만 있으면 어느 집 인덕션에서 요리하든 똑같은 맛이 나는 것처럼, 도커 상자만 있으면 **내 컴퓨터든 구글 서버든 토씨 하나 안 틀리고 똑같이 구동**됩니다!

## 3. ☁️ '구글 클라우드 런(Cloud Run)'이란? (주문 올 때만 켜지는 공유 주방)

웹사이트를 인터넷에 띄우려면 서버를 24시간 켜놓아야 합니다.

### 💸 기존 가상 서버 (VM) vs Cloud Run 차이점

| 구분 | 기존 가상 서버 (VM) | 구글 클라우드 런 (Cloud Run) ⭐️ |
| :--- | :--- | :--- |
| **비유** | 24시간 월세 가게 계약 | 주문 올 때만 켜지는 팝업 주방 |
| **새벽 3시 비용** | 손님 0명이어도 월세 100% 지불 | **손님 0명이면 인스턴스 0개 = 비용 0원** |
| **손님 폭주 시** | 가게가 좁아서 손님 튕겨나감 | 구글이 자동으로 요리사를 100명까지 늘려줌 |

i-Core 서비스는 **Google Cloud Run**을 사용하여, 손님이 접속할 때만 1초 만에 불이 켜지고, 사용을 안 할 때는 0개로 스케일다운되어 **비용을 획기적으로 아낍니다.**

## 4. 🤖 AI가 거짓말을 못 하게 만드는 '오픈북 테스트(RAG)' 원리

ChatGPT나 Gemini 같은 AI는 아는 척하며 가짜 정보를 진짜처럼 지어내는 습성(**할루시네이션**)이 있습니다.

> *"AI가 존재하지 않는 강사의 경력이나 자격증을 지어내서 추천하면 어떡하죠?"*

### 📖 i-Core의 3단계 해결법: "오픈북 테스트(RAG)"

```text
[ 1. Vector DB (지식 창고) ]  ➜  강사의 진짜 이력서만 잘게 쪼개어 보관
           │
           ▼
[ 2. Evidence Retriever (증거 돋보기) ]  ➜  100% 진짜 확인된 증거 문장만 핀셋 추출
           │
           ▼
[ 3. 2단계 AI 교차 검증 ]  ➜  에이전트 A(작성자) ↔ 에이전트 B(감시자) 교차 대조
```

1. **오픈북 테스트 방식 (RAG)**: AI에게 머릿속 기억으로 대답하지 말고, 우리가 건네준 **진짜 강사 이력서 지식창고(Vector DB)**만 펼쳐놓고 대답하게 만듭니다.
2. **AI 경찰관 (2단계 교차 검증)**: AI(에이전트 A)가 추천 사유를 쓰면, 또 다른 AI(에이전트 B)가 옆에서 **"이 말 진짜 이력서에 있는 내용 맞아?"** 하고 문장 단위로 검수하여 지어낸 글을 삭제합니다.

## 5. 🤖 'GitHub Actions (CI/CD)'란? (자동 재료 배달 로봇)

코드를 새로 수정할 때마다 매번 구글 클라우드에 들어가서 손으로 새로 올리려면 너무 귀찮습니다.

### 🚚 자동 배송 로봇 (CI/CD)
- 개발자가 컴퓨터에서 코드를 수정하고 **GitHub(코드 저장소)**에 올리기만 하면(`git push`),
- **GitHub Actions라는 자동 로봇**이 알아서 코드를 빌드하고, 구글 클라우드로 배달하여 웹사이트를 새 버전으로 교체해 줍니다.

## 6. 🎓 정리 한눈에 보기

```text
1. [코드 작성]   ➔ VS Code에서 예쁜 화면과 백엔드 로직 수정
2. [도커 포장]   ➔ 밀키트(Docker)처럼 어떤 환경에서든 똑같이 동작하도록 포장
3. [깃허브 푸시] ➔ git push 하면 자동 배달 로봇(GitHub Actions)이 작동
4. [구글 배포]   ➔ Google Cloud Run이 요청 올 때만 켜져서 0원 비용으로 서비스 제공
5. [AI 검증]     ➔ RAG 오픈북 방식으로 100% 팩트 기반 강사 자동 추천!
```

이제 여러분도 웹 개발과 클라우드, AI의 전체 커다란 그림을 이해하셨습니다! 🥳
